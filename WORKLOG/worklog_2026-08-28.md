## 任务17：列表页改为「点击查询」才过滤数据

- 时间：2026-08-28 16:10 - 16:50
- 执行人：Reasonix@Trae
- 类型：交互逻辑调整

### 任务描述

将全部带「查询」按钮的列表页从「修改筛选条件即时过滤」改为「点击查询后才过滤」。筛选区控件（Input/Select/DatePicker）仅持有表单临时值，点击「查询」时一次性应用到数据列表；「重置」清空表单并立即恢复默认数据。

### 技术方案

统一引入「表单值 filters + 生效值 applied」双状态模式：

- `filters`：筛选区控件绑定的临时值（输入/选择即改，不触发列表变化）
- `applied`：实际参与过滤的生效值；`applyFilters`（查询按钮）`setApplied(filters)`，`resetFilters` 同时清空 filters 与 applied
- 过滤 `useMemo` 依赖由 `filters` 改为 `applied`
- 分页型页面（warning/exception/work-order/goal/plan/followup 等）在 apply 时同时 `setPage(1)` 回首页
- 单值页面（checkin/assess/profile-tabs-Records）用「keyword + appliedKeyword」同构模式
- 含页签的页面（staff-audit/followup 等）：页签切换仍即时过滤（业务语义），仅搜索区改为点击查询
- leads/health-record 保留顶栏全局搜索带入的初始 keyword，并把该值同时作为 filters 与 applied 的初始值

### 结果

- 完全完成：20 个列表页全部改为点击查询过滤；`npm run type-check`（tsc --noEmit）与 `npm run build` 均通过
- 部分完成：health/profile-tabs「检验检查记录」过滤条为静态占位（4 个 Input 无绑定、表格数据固定 mockExams，无实际过滤逻辑），查询按钮保持装饰性，未引入无意义的过滤状态
