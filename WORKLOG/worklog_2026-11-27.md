## 任务1：服务简表、人员详情与连续派单修复

- 时间：2026-11-27
- 执行人：Kimi@Trae
- 类型：接口更新 / 人员详情 / 派单交互 / Bug 修复

### 任务描述

1. 新增 `ListAllServiceSimp` 接口：`GET /api/v1/staff/services/simp`。
2. 人员详情由原 `service_ids` 数字数组改为 `services` 服务对象数组，每项包含 `id / name / service_type`。
3. 用户期望派单时间早于当前时间时，默认派单时间改为当前时间。
4. 排查先给 A 派单、再给 B 派单时看板不显示 A 预约单的问题。

### 实现说明

- `staffApi.getAllServicesSimp()` 接入服务简表接口，新增支持分类树 `children` 的 `ServiceSimpleItem` 类型。
- `StaffDetail` 使用 `services?: ServiceSimpleItem[]`，人员详情授权项目展示服务名称与类型，不再展示服务 ID。
- 派单板打开和初始化方案时，过期或当前已到达的期望时间统一改用当前日期、当前分钟；未来期望时间仍沿用原值。
- 连续派单问题确认为前端解析与状态同步缺陷：
  - `/schedules` 已按 Swagger 返回 `service_schedules` 服务排期，原看板仅识别 `staff_id + start_time/end_time`，会忽略使用 `assigned_staff_id + planned_start_at/planned_stop_at` 的预约单。
  - 现同时兼容两类字段，并以会员、服务名称或工单号展示占用块，排除已取消服务排期。
  - 派单成功后立即将已派工单加入对应人员的占用时段，继续给其他工单派单时保持可见并参与冲突校验。

- 本次涉及文件的 `git diff --check`：通过，仅有 Git 的 LF/CRLF 转换提示。

## 任务2：新增人员流程与执业资质复用

- 时间：2026-11-27
- 执行人：Kimi@Trae
- 类型：交互优化 / 表单校验 / 接口联动

### 任务描述

1. 新增专业人员时复用 `credential-upload.tsx` 完成执业资质填写与文件上传。
2. 初始密码改为必填，采用简单明确的密码规则，并在输入框中展示。
3. 点击人员列表“新增人员”时先选择人员类型，新增页不再提供类型切换。

### 实现说明

- `CredentialUpload` 新增嵌入模式：独立页面仍按原路由人员 ID 直接保存资质；新增向导内仅同步资质类型、有效期和已上传文件 URL 草稿，不展示独立页面的标题与操作按钮。
- 专业人员第 2 步校验资质类型、有效期和至少一份上传成功的文件；组件在步骤间保持挂载，返回上一步不会丢失表单或文件。
- 最终提交先创建人员，再使用返回的人员 ID 创建执业资质。资质保存失败时单独提示“人员已保存，但资质保存失败，请在人员详情补录”，避免重试造成重复人员。
- 初始密码规则为 8–20 位，仅允许字母和数字且两者必须同时包含；placeholder 为“8-20 位，需包含字母和数字”，基本信息保存及下一步均执行校验。
- 人员列表新增类型选择弹窗，分别进入 `/staff/create?type=normal` 和 `/staff/create?type=pro`；新增页根据 query 固定人员类型，专业人员保留步骤条，普通用户不渲染步骤头部。
- 保留当前机构 `institution_id` 提交和按手机号查询回填逻辑，未恢复代码中已注释的人员关系等交互。

## 任务3：全项目状态标签样式统一

- 时间：2026-11-27
- 执行人：Kimi@Trae
- 类型：全局样式 / 组件统一 / 页面清理

### 任务描述

全项目状态标签统一使用全局 `.status-tag` 及 `green / blue / orange / red / teal / purple / gray` 色调，不再由各页面独立定义状态配色。

### 实现说明

- 确认 `src/styles/global.less` 已有与需求一致的全局 `.status-tag` 定义，保留为唯一外观来源。
- 新增 `src/components/StatusTag/index.tsx`，兼容现有 antd `Tag` 的 `color / className / variant` 用法，将 `success / processing / warning / error / cyan / magenta` 等颜色统一映射到全局状态色调，并输出 `.status-tag`。
- 24 个原使用 antd `Tag` 的页面、共 49 处标签改用统一组件；其他自定义标签直接迁移到 `.status-tag`。

- 仅保留标签在特定卡片中的定位、间距等布局样式；筛选胶囊、圆点、趋势图状态及纯文本状态不套用标签外观。
