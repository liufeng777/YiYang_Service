## 任务1：排单板新增「待分配池」（跨天共享）+ 修复拖拽落点偏移 bug

- 时间：2026-10-23 09:40 - 10:20
- 执行人：Kimi@Trae
- 类型：交互功能 / bug 修复

### 任务描述

1. 排单板表格上方增加一栏空白「待分配」栏：无期望人员**或**无期望时间的工单默认放入；人员行里的工单也可拖回池中重新分配；池子跨天共享，不受顶部日期筛选约束。
2. 修复 bug：工单块无法放入 08:00 右边第一格（无冲突也不行）。

### 技术方案

- **待分配池**：引入 `POOL_STAFF_ID = 0`，`plans[id].staffId === 0` 即视为入池。
  - 初始化规则调整：有期望人员匹配**且**有期望时间 → 默认期望方案；否则 → 待分配池（块水平位置取期望时间，无则 08:00 起）。原「无期望自动找空档」逻辑被池方案取代（用户明确要求）。
  - 池跨天共享：`poolOrders` 不按日期过滤；工单条 / 点选清单 = 当日工单 ∪ 池内工单。
  - 池内工单不参与冲突校验与计数（`conflictOf` / `tryPlace` 对 staffId=0 直接放行），不计入「可派」；底部汇总改为「共 X 单 · 待分配 Y 单 · 冲突 Z 单 · 可派 N 单」。
  - 池轨道可点选放置 / 拖放，人员行工单可拖回池；池内水平重叠的工单按区间泳道竖向堆叠，池行高度自适应（最低 52px，每泳道 46px）。
- **拖拽落点修复**：根因是旧逻辑把指针位置直接当块起点，未计算抓取点偏移——抓着长块中部想让块左边缘落在 08:00 时，指针实际在更靠后的格，块被放到了错误位置。修复：`dragStart` 记录 `offset = 指针分钟 - 块起始分钟`，drop / 点选放置时 `起点 = 指针分钟 - offset`，再吸附 30 分钟粒度并钳制在板内，块落在视觉上看到的位置。
- **样式**：池行浅色底 + 虚线下边框；池内块浅绿底 + 绿色虚线边框，与人员行实色块区分；空池显示「无待分配工单」提示；均使用 variables.less 既有变量与 mixins。
- **类型修复**：辅助函数签名中的 `React.DragEvent` / `React.MouseEvent` 改为从 'react' 显式 `import type`（严格模式下 React 命名空间不可用）。

### 结果

- 完全完成：待分配池（含跨天共享、拖回重分配）、拖拽落点偏移修复
