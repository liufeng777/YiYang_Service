## 任务1：工单详情载入当前派单并支持拖拽改派

- 时间：2026-11-28
- 执行人：Kimi@Trae
- 类型：服务工单 / 调整派单 / 拖拽改派

### 实现说明

- 工单详情打开“调整派单”时，将工单详情与排单详情合并，优先使用当前 `assigned_staff_id / staff_name / planned_start_at / planned_stop_at`，不再仅按客户期望人员和期望时间生成方案。
- 派单板识别 `schedule_id > 0` 且状态为待接单或待服务的工单，默认将可拖拽工单块放到当前服务人员的当前计划时段，并自动切换到对应日期；排单详情异步返回后也会同步当前派单数据。
- 当前服务人员不在在职候选列表时，保留其真实人员行用于展示当前安排；关闭面板后销毁本次调整状态，避免旧方案残留。
- 加载 `orders/by-staff` 占用数据时，按 `work_order_id / work_order_no` 排除当前改派工单自身，避免旧占用与当前方案重复或产生自身冲突；其他工单仍正常参与冲突检测。
- 用户可沿用现有拖拽、点选空档和日期切换交互调整服务人员与时间。确认时，新工单仍调用 `work-orders/{id}/dispatch`，已派工单改为调用 `service-schedules/{id}/reassign`，提交新服务人员、计划起止时间及默认调整原因。
- 调整派单模式的标题、操作提示、冲突状态、数量和确认按钮均改为改派语义；成功后关闭面板并刷新工单详情。

## 任务3：修复改派本单被渲染为灰色禁用并进入待分配池

- 时间：2026-11-28
- 执行人：Kimi@Trae
- 类型：服务工单 / 改派面板 / Bug 修复

### 问题原因

- 原 `isReassignOrder` 同时要求 `schedule_id > 0` 和状态为待接单 / 待服务。详情未返回有效排单 ID 时，已派工单会被误判为新派单：初始化逻辑将其放入待分配池，`by-staff` 中的本单也无法命中改派匹配，最终被渲染为灰色禁用占用块。

### 实现说明

- 改派识别改为以工单状态 `2 / 3` 为准，并用 `Number` 兼容数字字符串，不再依赖 `schedule_id` 决定是否进入改派模式。
- `by-staff` 渲染时直接比较 `item.work_order_no` 与当前面板工单号，命中即认定为本单，不再附加排单 ID 或状态完整性条件。
- 本单从灰色、不可拖拽的 `wo-board__busy` 中排除，按匹配到的 `staff_id / planned_start_at` 写入可拖拽绿色方案，同时从待分配池移除；其他非本单工单继续渲染为灰色禁用占用块并参与冲突检测。
