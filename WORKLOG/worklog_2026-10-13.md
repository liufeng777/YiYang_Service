### 任务描述

整个应用的接口 json 已更新（`src/api/swagger.json`，openapi 2.0，72 个端点，全部 `/api/v1/staff` 前缀），要求按照最新接口 json 修改 api 中各个接口以及对应的页面。

### 技术方案

- **request.ts**：恢复响应拦截器注释掉的 Authorization: Bearer token 注入（此前被注释导致所有请求未带 token）。
- **auth**：sms-login 入参 `{phone, code}`（原 sms_code）；sms-code scene 枚举改 `'login'|'reset'`；新增 `auth/refresh` 刷新令牌、`auth/switch-institution` 切换机构（返回绑定目标机构的新 JWT 及岗位，结构同 LoginResult）。
- **lead 整文件重写**：状态机对齐 swagger（1待跟进 2跟进中 3已转化 4转化失败 9流失）；assign 改 PUT `/leads/{id}/assign` body `{assignee}`；transfer / followup / lost / convert 签名全部对齐；新增 batch-transfer、export（CSV blob）、import（multipart）。
- **consult 整文件重写**：list 加 keyword；新增 create / detail / update(PUT) / delete；删除 reply 端点（回复改 PUT `{answer, status:2}`）。
- **warning**：状态字典扩展 {0待处理 1待处理 2已处理 3已忽略 4已处置(继续服务) 5已处置(中止服务)}；warning_source 改 number；handle 入参加 `warning_status: 3|4|5`。
- **followup**：complete 入参改可选（swagger 仅路径参数无 body）。
- **staff**：列表筛选 position_id → `position_code`（string）；createStaff 扩展参数同步改 position_code。
- **member**：列表参数删 status / nursing_home_id / station_id，加 care_level / institution_id；新增 `PUT members/active-status` 与 assessments 详情 / 确认两个端点。
- **order / refund 重写**：order 对齐待确定订单流程（pending-confirm 列表 / detail / confirm / reject）；refund 对齐审批流程（列表 / detail / approve `{approve, opinion}` / logs）。
- **新建模块**：appointment（预约 CRUD + cancel / status / visit）、schedule（排班 CRUD + day/week/month 视图）、relation（会员-人员服务关系 bind / unbind / active_only）。
- **页面更新**：
  - select-org：进入机构先调 `switch-institution` 换新 token 与该机构岗位/权限，成功才进入工作台；按钮加 loading。
  - consultation/register：来电登记提交对接 `POST /consultations`（consultation_type=3 电话），主题/服务对象/来源/跟进时间拼入 question。
  - work-order/audit：按路由 id 拉取订单详情渲染会员条，审核通过 → `confirmOrder`，不通过/退回 → `rejectOrder`；audit-result 页工单号改取路由 id。
  - leads/index：新增「导出」按钮，按当前筛选条件调 exportLeads（blob）前端触发 CSV 下载。
  - BasicLayout NO_API_PREFIXES 移除 `/consultation/register`、`/work-order/audit`（两者已对接真实接口）。
  - staff/create、staff/list：岗位选择 value 由 id 改 position_code。
- **保持「暂未对接接口」的模块**（swagger 无端点）：activity、institution、team、role、exception、health 导入/专病/分层、followup 问卷向导、全局 goal/plan/assess 列表（仅有 per-member 端点）。
