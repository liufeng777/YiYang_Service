# 工作日志 2026-11-19

## 任务1：接入站内消息与触达设置，修正家族史和健康方案字段

- 时间：2026-11-19
- 执行人：Kimi@Trae
- 类型：站内消息 / 触达偏好 / 健康档案 / 健康方案

### 任务描述

根据最新 `src/api/swagger.json` 补齐新增的站内消息、未读数、已读处理、触达偏好及微信订阅接口和页面；将家族史“是否已故”改为 Radio；健康方案起止日期统一使用 UTC 秒级时间戳。

### 技术方案

- **消息接口**：新增消息列表、详情、批量已读、全部已读、未读数、触达偏好读写及微信订阅状态读写方法，并统一从 `@/api` 导出。
- **消息中心**：顶部导航增加未读角标和消息入口；列表支持消息类型、读取状态、业务对象类型筛选及分页；查看详情后刷新列表与未读数，支持批量和按当前分类全部已读。
- **触达设置**：支持关闭消息分类、夜间免打扰、短信和微信触达开关；微信订阅支持模板码查询、未订阅/一次性/长期状态、剩余次数及有效期保存。
- **通用响应兼容**：Swagger 对消息响应仍只声明通用 `object`，页面对消息标题、正文、时间和未读总数的常见字段做兼容读取，不新增文档之外的接口行为。
- **家族史**：`is_dead` 明确为 `0 | 1`，新增和编辑使用“否 / 是”Radio，新增默认值为 0；列表空值显示 `-`。
- **方案日期**：`HealthPlan.start_date/end_date` 改为数字秒级时间戳；列表、详情和执行状态均乘以 1000 转为 dayjs，编辑器回显只接收秒级数字，保存仍以当天开始/结束的 Unix 秒提交。

### 接口与页面注意事项

1. 消息列表、详情和未读数的响应 schema 未在 Swagger 中展开，真实返回字段仍需后端联调确认；当前已保留扩展字段并提供常见命名兼容。
2. 微信订阅模板码需要业务方提供，页面仅按文档示例提示 `WO_ASSIGNED`，未硬编码模板列表。
3. 健康方案接口文档的请求和响应仍为通用 object，日期类型按本次明确约定统一为 UTC 秒。

## 任务2：修正工作台导航、统一按钮规范并接入敏感信息脱敏

- 时间：2026-11-19
- 执行人：Kimi@Trae
- 类型：布局 / 工作台 / 样式规范 / 隐私保护

### 任务描述

移除右上角无跳转目标的“个人中心”；将工作台待审核服务订单入口改为订单审核，各角色入口统一使用“进入处理”；统一全项目按钮视觉规范；对姓名、手机号、身份证号和详细地址提供默认脱敏及按需查看能力。

### 技术方案

- **顶部与工作台**：顶栏仅保留消息、机构、账号和退出相关功能；待审核服务订单跳转 `/order-audit`，各角色待办入口统一为“进入处理”。
- **按钮规范**：通过 antd 主题 token 与全局 Less 统一主按钮实心绿、次要按钮绿框白底、危险按钮红框白底，文字及链接型危险按钮保留轻量样式。
- **公共脱敏组件**：新增 `SensitiveText`，导出 `maskName`、`maskPhone`、`maskIdCard`、`maskAddress` 和 `maskSensitive`。姓名保留首字或英文首字母，手机号和身份证保留前 3 位及后 4 位，地址默认显示到区/县/旗；眼睛按钮仅在当前组件内切换原文，值变化后自动恢复隐藏。
- **业务页面接入**：会员、健康档案、健康方案、人员、机构、团队、咨询、工单、订单审核、随访、预警、活动、入住、测评和线索等展示场景统一接入；下拉选项、提示消息和纯文本标题使用掩码函数。
- **录入与公开信息边界**：新增、编辑表单仍保留原始输入，避免影响提交；机构地址、活动地点和机构公开联系电话不按个人敏感信息处理，机构负责人姓名和个人手机仍脱敏。
