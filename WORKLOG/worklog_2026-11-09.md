# 工作日志 2026-11-09

## 任务1：按 staff Swagger 更新 API 模块与对应 UI

- 时间：2026-11-09
- 执行人：Kimi@Trae
- 类型：接口对接 / 页面重构 / 去 mock

### 任务描述

以 `src/api/swagger.json`（协同工作台端 staff）为唯一接口准绳，校正 API 请求模块，更新会员、测评、随访、预约、活动、人员和机构等页面，补充健康服务接入，并清理当前路由内的模拟数据与无接口假成功操作。

### 技术方案

- **API 模块**：按 staff 文档整理 21 个请求模块，共 161 个 `http` 请求方法；新增健康档案、健康服务接入、健康方案、指标、慢病字典和上传模块，移除不属于 staff 文档的服务、内容、系统、财务、消息和独立关系模块导出。
- **会员**：列表筛选调整为 `keyword / risk_level / care_level / institution_id`；详情聚合 `health-profile` 与 `health-archives/overview`，对通用响应做安全展示，删除实名、团队归属和保存配置等无接口状态。
- **测评**：改为选择会员、分页查询、创建、查看原始数据、查看详情和专业确认的真实请求链路。题目、六维分析和附件不再使用 mock；通用 object 请求与响应显式展示。
- **随访**：创建页调用会员随访创建接口；执行页调用完成接口，并明确问卷、草稿和自动写档案等能力未建模。
- **健康服务接入**：新增列表、新建、详情、分配、确认、跟进、拒绝和转派 UI，接入对应 8 个请求方法。
- **预约与活动**：预约创建日期改为 UTC 秒，移除创建模型的 `member_id`，兼容列表数字日期；状态回写支持备注。活动不再猜测状态枚举，可选时间为空时安全显示。
- **人员与机构**：资质文件先经上传接口保存，再新增人员资质；删除 OCR、统一审核假流程。机构只保留 `institutions/current` 页面。
- **路由清理**：移除测评模板、机构新增/详情、工单 mock 审核、统一资质审核、派单资格总览及独立服务授权等无对应端点的页面入口。

### 接口与 UI 不匹配记录

1. 多数响应只声明 `pkg.Response.data: {}`，列表、详情和通用 object 请求体的精确字段仍需后端补充。
2. 随访问卷、草稿、随访小结、自动写档案及生成下次任务没有结构化提交接口。
3. 测评模板、题目版本、六维评分、AI 结论和附件关系未建模；确认接口同时声明两个 body 参数，需后端明确实际 JSON 包装方式。
4. 检查检验、用药记录、健康事件时间轴、团队分配、实名审核留痕等旧 UI 无对应 staff 接口。
5. 机构仅有当前机构查询；工单催单、联系结果回写、统一资质审核、独立服务授权和派单资格综合校验无接口。
6. 批量派单、评估、随访创建等部分请求体仅为 object；健康档案详细 CRUD、指标/慢病字典、方案/目标等 API 尚未全部提供独立 UI。

## 任务2：健康会员接入与健康档案工作台

- 时间：2026-11-09
- 执行人：Kimi@Trae
- 类型：页面重构 / 真实接口对接 / 搜索栏统一

### 任务描述

统一各列表搜索栏布局；健康会员改用 `staff/health-accesses` 接入流程；移除“健康服务接入”导航，在健康会员上方新增“健康档案”，并补齐档案、病史、慢病、指标、目标与方案维护 UI。

### 技术方案

- **健康会员**：列表、新增、详情、分配、确认、跟进、拒绝和转派均调用 `healthAccessApi`；会员与健管师接口仅用于登记/分配时的下拉选择。
- **健康档案列表**：按要求调用 `GET /api/v1/staff/health-accesses`，以 `member_id` 跳转 `/health-record/:id`。
- **主档案与病史**：接入档案概览、主档案保存、生活习惯保存，以及过敏史、既往疾病史、家族史、手术史的增删改查；日期按 UTC 秒提交。
- **慢病专病**：接入专病列表、新建及当次评估、控制状态变更、终止、评估列表/详情/更新，以及慢病字典和按病种查询的评估指标字典。
- **指标**：接入指标记录分页、新增、修改和多指标趋势查询；监测项字典用于指标选择，并展示字典详情、参考范围及关联慢病。
- **目标与方案**：接入健康目标列表/新增、目标指标项更新、健康方案列表、AI 生成、详情、确认和放弃。
- **导航**：新增“健康档案”，删除“健康服务接入”路由和页面文件；健康会员旧详情入口移除，订单审核中的健康档案链接改到新工作台。
- **搜索栏**：健康会员、健康档案、健康力测评、入住协同、随访、订单审核、咨询、工单、预警、活动报名和现场签到统一使用 `Card.filter-bar`，按钮顺序统一为“重置 → 查询”。

### 接口与 UI 不匹配记录

1. 健康档案列表按需求复用健康服务接入名单，并非独立档案列表；同一会员若有多条接入记录，列表可能出现重复会员，且接口未提供“档案是否已建立”标识。
2. 健康目标、新增目标、目标指标项和 AI 方案请求体在 Swagger 中仅为通用 `object`，无法生成可靠的业务表单，当前提供 JSON 对象编辑入口并做格式校验，仍需后端补充字段模型。
3. 档案概览、指标趋势、方案详情和专病指标字典等响应只声明通用 `pkg.Response`，具体结构不明确；当前采用兼容读取和 JSON 展示，趋势图及更精细的档案展示需后端补充响应示例。
4. 主档案、生活习惯、来源和部分状态字段仅有数值类型，没有完整枚举字典，因此相关录入保留数值输入或原值展示，未虚构中文枚举。
5. 健康接入文档未给出各状态允许执行的操作约束，当前处理抽屉提供全部流程操作，实际状态流转由后端校验。
