## 任务22：选择机构页对接机构详情 + 权限码体系切换到 staffPermissions

- 时间：2026-10-14 10:05 - 10:40
- 执行人：Kimi@Trae
- 类型：接口对接 / 权限体系改造

### 任务描述

1. 登录后根据 staff.institutions 数组中每一项的 institution_id 调用 getInstitutionDetail，渲染 select-org 页机构卡片信息。
2. 登录后选择机构，switch-institution 接口返回 permissions（staffPermissions 子集），根据 permissions 渲染左侧导航及后续对应界面。

### 技术方案

- **institution.ts 重写为协同工作台端模块**：新增 `getInstitutionDetail(id)`（GET `/v1/staff/institutions/{id}`，出参字段全部可选兼容）。注意：该端点未出现在 swagger.json 路径清单中，路径按网关前缀约定推断，如后端实际路径不同仅需改此一处；旧的运营端脚手架接口（无页面引用）一并移除。
- **select-org 页**：新增 details 缓存（key=institution_id），useEffect 中对 institutions 逐项并发拉取机构详情并合并进卡片（名称/类型/数据范围/地址）；单个机构详情失败不阻塞页面，卡片回退为登录接口返回的基础信息。
- **切换机构**：onEnter 调 `switch-institution` 后，除新 token 外同步更新岗位编码（导出共用 resolvePositionCode）、岗位名、机构名与 permissions（接口返回的 staffPermissions 子集）；侧边栏与路由守卫随即按新权限重新渲染。
- **权限码体系切换（旧码 → 后端 staffPermissions）**：
  - routes.tsx PERMISSIONS 常量全部改为新码：staff:dashboard→dashboard:view、health:view→member:view、health:assess→assessment:view、health:goal→goal:view、health:plan→plan:view、health:plan-ai→plan:edit、staff:followup→followup:view、warn:view→warning:view、wo:view→work_order:view、wo:dispatch→work_order:edit、consult:view→consultation:view、staffmgr:view→staff:view；activity/org/team/role 后端无对应码，保留预留码不变。
  - menu.tsx hasAccess 新增 `all:manage`（机构管理员全量权限）特判放行；导出 ALL_MANAGE_PERMISSION 常量。
  - user.ts POSITION_PERMISSIONS 兜底权限集全部改为新码，机构管理员兜底直接用 ['all:manage']。
  - workbench/components.tsx 快捷入口过滤同样支持 all:manage 放行（其配置经 PERMISSIONS 常量自动跟随新码）。
- **修复**：lead 模块重写时遗漏的 CONTACT_IDENTITY_MAP 与 LeadItem.contact_identity 字段补回（leads/edit、verify、mock 三处引用）。

### 结果

- 完全完成：机构详情逐个拉取渲染卡片；切换机构后按返回 permissions 渲染导航与页面；权限码体系全量切换
- 验证：`npm run type-check` 通过、`npm run build` 成功（vite，1.20s）——同时覆盖了任务21（swagger 对齐）遗留的验证缺口
