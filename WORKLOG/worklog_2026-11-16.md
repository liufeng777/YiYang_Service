## 任务1：按最新 Swagger 重构健康方案接口与页面

- 时间：2026-11-16
- 执行人：Kimi@Trae
- 类型：健康方案 / 审核流程 / 方案打卡

### 任务描述

依据 `src/api/swagger.json` 中最新的健康方案接口，更新 API 模块和健康档案详情中的健康方案页面，移除已经不在文档中的旧接口及对应交互。

### 技术方案

- **方案列表与创建**：使用 `GET/POST /api/v1/staff/members/{id}/plans`，支持草稿、健管师通过、医生确认、已中止状态筛选；创建和编辑均明确提交 `goals`、`interventions`。
- **方案详情与编辑**：使用 `GET/PUT /api/v1/staff/plans/{id}`；详情以方案信息、健康目标、干预措施、审核履历四个维度结构化展示，编辑仅对状态 1、2 开放。
- **两轮审核**：使用 `POST /api/v1/staff/plans/{id}/review`，页面按当前状态提示健管师审核或医生确认，支持通过和驳回。
- **方案中止**：保留 `POST /api/v1/staff/plans/{id}/abandon` 二次确认，状态 9 不再显示编辑、审核和中止操作。
- **方案打卡**：新增打卡管理 Drawer，接入应打卡清单、打卡统计、打卡历史及健管师代录打卡接口；支持日期区间、干预 ID 和历史分页查询。
- **旧功能清理**：删除独立健康目标列表/创建、目标指标项维护、AI 生成旧路径和确认采用旧路径；一级页签由“目标与方案”改为“健康方案”。

### 接口与 UI 差异

1. 新文档不再包含 `/members/{id}/goals`、`/goals/{id}/items`、`/plans/ai-generate` 和 `/plans/{id}/confirm`；目标随方案统一创建和覆盖编辑，审核统一走 `/review`。
2. Swagger 中方案创建/编辑、打卡请求及响应仍主要声明为通用 `object`，未提供目标、干预的逐字段 schema。因此编辑区保留 `goals`、`interventions`、`items` 的 JSON 校验，不虚构业务字段；详情使用结构化 DataView 展示实际返回字段。
3. `/plans/{id}/review` 的描述明确使用 `pass=true/false`，但文档未声明 body 参数；前端按描述发送 JSON `{ pass }`，仍需后端联调确认。
4. 应打卡接口路径以文档实际拼写 `/checkin-dued` 为准。
5. 本次未连接真实后端验证角色审核权限、目标/干预字段和打卡统计响应结构。

## 任务2：检测项管理 Tree 对齐、操作菜单与列表滚动修复

- 时间：2026-11-16
- 执行人：Kimi@Trae
- 类型：检测项管理 / Tree / Table 布局

### 任务描述

修复检测项分类 Tree 的展开开关与标题高度不齐、窄空间下操作 Dropdown 过于靠右，以及检测项列表内容溢出时无法滚动的问题。

### 技术方案

- **Tree 垂直对齐**：节点行统一垂直居中，展开开关与标题使用一致的行高；标题区域改为 flex 并保留最小宽度约束，名称和编码继续省略显示。
- **Dropdown 定位**：操作菜单使用 `placement="bottomRight"` 并开启自动边界调整，让菜单向树区域内侧展开，降低右侧溢出风险。
- **表格独立滚动**：右侧检测项 Card 改为纵向 flex，头部、分类上下文、筛选栏和分页保持固定；新增 `.mm-table-scroll` 贯通 Table Wrapper、Spin、Table、Container 和 Body 的高度链，内容溢出时仅表体滚动。
- 保留现有固定列、横向滚动、分页及分类树交互，不调整接口和业务逻辑。
